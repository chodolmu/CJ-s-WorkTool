## 3. Missing candidates

### M-1 — Rule 14 allowlist staleness audit (defect class: allowlist rot)

**Evidence**: `.rule14-allowlist.txt` has 9 entries (gmk-art-gen:140, brainstorm:24, kill-milestone:145, loop:128, loop:243, merge-gate:156, merge-gate:297, mock-inject:26, save-migrate:196). Each was justified at the time of v0.7's line-level migration. **None has a re-verification date.** If a SKILL is edited and the allowlisted line *moves* to a new line number (or the line at that number becomes a real refuse), the allowlist silently goes stale.

The endpoint-allowlist analog (Candidate #1 finding above) already has a stale entry. The Rule 14 allowlist almost certainly has the same problem latent — but checking it is a 5-minute audit, not a sweep.

**Proposed candidate**: *"Re-verify every allowlist entry (Rule 14 + endpoint) against current file line numbers. Add a comment per entry recording the SHA of the SKILL file at time of justification, so future audits can detect 'has the file changed since this allowlist entry was justified?'"*

**Defect class**: same as half-applied standard — allowlist entries are *declared as justified once* and never re-checked.

### M-2 — Rule 14 CYCLE form: dead-code reframing in v0.7 vs other "unused safety valve" patterns

**Evidence**: HANDOFF L21 mentions v0.7 reframed Rule 14 CYCLE as *"fallback / currently unused safety valve"* instead of deleting. The pattern (declared form, zero current usage) likely applies elsewhere:

- `kit_version: kit_version > current` (Rule 16 row 3): the "warn but proceed" branch has zero use because no file in the repo declares a kit_version greater than 0.7.0. The branch is correctly defensive (downgrade scenario), but its existence is the same defect class — **declared, possibly never exercised in the lifetime of the kit**.
- `early_fail` field in `measured_by[]` (milestones-example.json:21) — verify whether `gmk-validate` actually reads it for early termination, or whether it's another write-only field.
- `Math.random()` warning (Rule prototype-rules L496) — verify whether any prototype currently triggers it. If not, the warning is dead.

**Proposed candidate**: *"Audit kit for declared-but-never-exercised behaviors. Each one is a Rule 14 CYCLE situation in waiting — code that will rot silently because no test path exercises it. Either add a synthetic test invocation or document it as 'safety valve' with explicit 'last-exercised: never' notation. Same defect-class as half-applied standards."*

This is broader than M-1; treat as **a candidate for v0.9 if v0.8 is full**.
