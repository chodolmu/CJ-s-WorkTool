S4가 푸는 것:
1. **gmk-confirm SKILL 신설** — 빌드된 module HTML + genre-decisions convention 매핑을 읽어, **컨펌 전용 시각 페이지** `_workspace/s*-test/confirm/<Mn>-confirm.html`(실프로젝트는 `.gamemaker-kit/confirm/`)를 생성. 이 페이지는: (a) module HTML iframe/스크린샷, (b) 이 module이 책임지는 convention 목록(numeric=bot이 잰 값, needs_metric=관측 항목), (c) 각 항목 Y/N 체크박스, (d) 사용자 판정을 구조화 JSON으로 export하는 버튼.
2. **Confirmation latency 디자인** (concept §8 deferred #1, backlog가 S4로 지정) — 사용자가 *즉시* 컨펌 못 할 때(자리 비움/모바일)의 처리. 컨펌 페이지가 *상태를 잃지 않고* 다음 세션에 재개되도록.
3. **module-build와의 계약** — module-build Step 5(텍스트 컴폼)와 gmk-confirm(시각 컴폼)의 관계 명시: 둘 다 같은 `confirm` 필드에 쓰되, gmk-confirm이 *덮어쓰는 권위 있는 시각 컨펌*. 빠른 경로(텍스트)는 사용자가 시각 페이지 원치 않을 때.

**왜 신설인가**: P5는 *playable build마다* 적용되는 횡단 관심사. module-build에 박으면 다른 build 경로(차별화 gmk-prototype, 추후 port된 빌드)가 못 씀. 별도 SKILL이라야 재사용.

## §3 module-build Step 5 vs gmk-confirm 계약 (계층 분리)

| 차원 | module-build Step 5 (기존) | gmk-confirm (신규) |
|------|---------------------------|-------------------|
| 형식 | 텍스트 per-convention Y/N (채팅) | 시각 .html 페이지 (new-tab 플레이 링크 + `<select>` 행 + paste-textarea) |
| 시점 | 빌드 직후, 빠른 inline 확인 | 별도 호출, P5 정식 시각 컨펌 |
| 쓰는 곳 | milestones.json `confirm` | 같은 `confirm` 필드 — gmk-confirm이 권위 있게 *덮어씀* (`confirm.method: "visual"`) |
| 언제 | 사용자가 시각 페이지 불필요할 때 (expert 빠른 경로) | playable build를 *시각으로* 검토할 때 (P5 기본) |

**필드 호환**: 둘 다 `{confirmed, per_convention, notes}` 구조. gmk-confirm은 `method: "visual"` + `status` + `confirmed_at` + (latency용) `confirm_html` 경로를 추가. module-build Step 5 출력에 method 없으면 `"text"`로 간주. **gmk-confirm은 module-build를 수정하지 않음** — 같은 필드에 쓸 뿐. (B9: module-build는 영향 없음, read-side 계약 동일.)

**Last-writer-wins 충돌 (M2 — 명시):** 두 SKILL이 같은 `confirm` 객체를 *통째로 덮어쓰므로* 순서에 따라 충돌한다:
- module-build Step 5(text) → gmk-confirm(visual): 정상. visual이 권위 있게 덮음.
- gmk-confirm(visual) → module-build **재실행**(fidelity 미스 후 재빌드): module-build Step 5가 confirm 객체를 *text shape로 되돌림* — gmk-confirm의 `method:"visual"`/`confirm_html`/`confirmed_at`이 **silent 소실**된다. 이건 module-build를 수정 안 하기로 한 §0 결정의 불가피한 귀결.
- **규약 (drift 방지)**: module-build 재실행 = 빌드가 바뀐 것 = *이전 시각 컨펌은 무효화되는 게 맞다*. 따라서 이 clobber는 의도된 동작. 단 gmk-confirm Step 0이 "이 빌드의 confirm이 text method인데 visual confirm 페이지(`<Mn>-confirm.html`)가 디스크에 이미 있으면 = 재빌드로 무효화된 것" → "재빌드됨, 시각 컨펌 다시 하세요" 안내 후 새로 생성. (§7 fallback에도 기재.)

## §4 gmk-confirm SKILL 절차 (신규)

### Frontmatter
```yaml
name: gmk-confirm
description: Render a visual .html confirmation page for a playable build — embeds the module prototype, lists the conventions it must honor (numeric ones with the bot-measured value, qualitative ones as observe-and-check rows), and captures the user's per-convention Y/N verdict as structured JSON. The concept-P5 check-in gate: every playable build gets a human look before it advances. Use when the user says "/gmk-confirm <Mn>", "confirm the build", "컨펌 화면", "check-in", or after /gmk-module-build produced a playable HTML. Writes a confirm page + records the verdict in milestones.json. Latency-safe — the page persists state so confirmation can finish in a later session.
model: sonnet
```

### Step 0 — Verify (disk + git, 첫 sub-step, P8)
1. 대상 milestone이 milestones.json에 존재 + `prototype` 경로의 HTML 파일 실재.
2. genre-decisions.json 존재 + JSON.parse + 대상 module의 covers_conventions가 거기 있음.
3. **mode 검사 (m3 — §6 deferral과 일치)**: 대상 milestone이 `mode: "reference-clone"`이어야 함 (gmk-module-build 산출, covers_conventions 보유). `mode != "reference-clone"`(blank-page 차별화 build)면 **STOP** — *"이 build는 blank-page/차별화 mode. 시각 컨펌의 hypothesis-row 버전은 후속 detail에서 (현재 S4는 reference-clone module 컨펌만)."* blank-page 시각 컨펌은 이 detail 범위 밖 (§6, P6 one-detail-at-a-time).
4. 실패 fallback: HTML 없음 → STOP (*"빌드 HTML이 없음. /gmk-module-build 먼저."*).

### Step 1 — Read build + contract
- milestone entry: prototype 경로, covers_conventions, validation(있으면 numeric 측정값 + verdict), mode.
- 각 covered convention: statement + acceptance(numeric) / needs_metric(qualitative) 분리.
- numeric convention은 validation에서 *측정값*을 끌어옴 (예: C9 late_level_moves=15, gate [12,18] → "✓ 15 in [12,18]"). 측정값 없으면(validation null) "측정 대기" 표시.

### Step 2 — Render confirm page (시각 .html 생성)
컨펌 전용 페이지 `<confirm-dir>/<Mn>-confirm.html` 생성. 구조 (단일 파일, vanilla, 외부 의존 금지. 프로토타입 아니라 *컨펌 도구*라 300/600 line cap 면제 — **단 m4: 페이지는 covers_conventions에서 data-driven으로 생성되므로 크기가 convention 수에 비례해야 함**. convention 5개에 500줄 넘으면 도구가 비대해진 신호, 재검토):
- **상단**: module 이름 + pillar + reference URL.
- **중앙 좌 (m1 — new-tab 기본, iframe 옵션)**: module을 **"새 탭에서 플레이" 버튼/링크가 1차 경로** (`<a href="../prototypes/<Mn>-*.html" target="_blank">`) — file:// 환경에서 iframe cross-origin 샌드박스 실패가 흔하므로 iframe에 의존하지 않는다. iframe(`<iframe src=...>`)은 *되면 보너스*로 함께 넣되, 안 떠도 컨펌 흐름(우측 체크리스트 + 저장)은 그대로 작동. 스크린샷 placeholder는 수동 첨부용.
- **중앙 우**: convention 체크리스트 —
  - numeric: `C9 late_level_moves [12,18] — bot 측정: 15 ✓ | 화면에서도 맞나? [Y/N]`
  - needs_metric: `C7 <statement> — 화면에서 관측됨? [Y/N]`
  - 각 행에 raw checkbox (Y/N/skip).
- **하단**: free-text notes textarea + **"판정 텍스트 생성" 버튼** → 모든 행의 verdict + notes를 JSON으로 직렬화해 **화면의 `<textarea readonly>`에 표시**(전체선택+복사 쉽게). 1차 capture는 이 텍스트를 **사용자가 채팅에 붙여넣는 것** (F1 — file:// 페이지는 repo에 파일 못 쓰므로 download 의존 안 함). download 버튼은 *보너스*(되는 환경에서만).
- **행 DOM 모델 명세 (F4 — Sonnet 재현성)**: 각 convention 행 = 하나의 `<select>` with options `["", "Y", "N", "skip"]` (빈값=미응답). verdict JSON: `per_convention[<Cid>] = true(Y) | false(N) | "skip"`. `confirmed = (모든 numeric+needs_metric 행이 "Y")`. "판정 텍스트 생성"은 빈값(미응답) 행 있으면 비활성(`disabled`) + "N개 미응답" 표시. localStorage key = `gmk-confirm-<Mn>` (단일, 페이지 새로고침 시 체크상태 복원 — UI 편의 only, F2).
- S4 quit signal 대응: 페이지 최상단에 *"코드 말고 이 화면으로 판단하세요"* 배너. 사용자가 코드 들여다보면 STOP은 *사용자 행동* 신호 — SKILL은 배너로 유도, Claude가 사용자가 "코드부터 보여줘" 하면 §7 STOP.

### Step 3 — Latency-safe state — **single source of truth = milestones.json.confirm (F2/F3)**
컨펌은 *즉시 안 끝날 수 있음* (사용자 자리 비움 / 모바일 / 나중에). 핵심 원칙 (Codex F2/F3 — recoverable agent state는 *디스크*에만 있다):

- **agent-recoverable state는 milestones.json `confirm` 필드 하나뿐 (single source of truth).** 새 Claude 세션은 browser localStorage를 *못 읽음* — 디스크 파일만 읽음. 따라서:
  - **localStorage = UI-only** (페이지 새로고침 시 체크상태 복원하는 편의일 뿐, recovery 아님 — F2). 사용자가 체크만 하고 채팅 붙여넣기/Claude 반영 안 하면 그 상태는 *agent에게 존재하지 않는다*. 페이지에 명시: *"체크만으론 저장 안 됨 — 판정 텍스트를 채팅에 붙여넣어야 기록됩니다."*
  - confirm 페이지 .html 파일 자체는 자기완결적(서버 불필요)이지만 *판정 결과의 권위 소스 아님* — 판정은 Step 4에서 Claude가 milestones.json에 씀.
- **port-blocking gate는 `confirm.confirmed`에 탄다 (M1 — gmk-port가 읽는 유일한 필드).** gmk-confirm이 페이지를 *생성하며 field 권위를 가져가는 순간*, milestones.json `confirm`을 다음으로 덮어쓴다 (Claude가 씀, 브라우저 아님):
  ```json
  "confirm": { "method": "visual", "confirmed": false, "status": "pending", "per_convention": {}, "confirm_html": "<경로>", "confirmed_at": null }
  ```
  **pending = `confirmed: false`로 강등** → gmk-port의 기존 `confirm.confirmed === true` 게이트(S3 §5.3 2-rc)가 *실제로* 막는다. `status`는 사람이 읽는 resume 힌트일 뿐 gate 아님.
- 사용자가 판정 완료(Step 4)하면 Claude가 `confirmed`를 실제 값으로, `status:"done"`, `confirmed_at` 채움.
- **다음 세션 재개 (F3 precedence)**: Step 0이 milestones.json `confirm`만 본다 (localStorage·다운로드 파일 *안* 봄 — 디스크 confirm 필드가 단독 권위). `status:"pending"`+`confirmed:false`면 "컨펌 대기, port 막힘, 페이지: <경로> 다시 열어 판정 후 채팅 붙여넣기". 사용자가 새 판정 텍스트 붙여넣으면 Claude가 module-id + covers_conventions 매칭 확인 후 반영 (mismatch면 거부 — stale 페이지 방지, F3).
- resume.md에 컨펌 pending이면 *위험 신호*로 기록.

### Step 4 — Capture verdict — **paste-to-chat 1차 (F1 — file:// write 우회)**
- **1차 경로 (F1): 사용자가 페이지의 판정 텍스트(JSON)를 *채팅에 붙여넣고*, Claude가 받아 milestones.json에 씀.** file:// 페이지는 repo 경로에 파일을 *못 쓰므로* download-to-repo에 의존하지 않는다. Claude가 디스크 쓰기 주체. (download 버튼은 페이지가 제공하지만 보너스 — 다운로드 폴더에 갈 뿐, Claude는 paste된 텍스트를 신뢰.)
- **paste 검증 (F3 — stale/mismatch 방지)**: 붙여넣은 JSON을 milestones.json에 반영하기 *전*에 Claude가 확인 — (a) JSON.parse 성공, (b) `module_id`/`<Mn>` 일치, (c) per_convention 키 집합 == 대상 module의 covers_conventions 집합. 하나라도 mismatch면 거부 (*"이 판정은 다른 module/오래된 페이지 것 같음 — 현재 <Mn> 페이지에서 다시"*). paste가 checksum 없는 약한 seam이라던 우려(원 m2)를 이 3-검사로 메움.
- 붙여넣을 JSON 구조: `{ method: "visual", module_id: "<Mn>", confirmed: <모든 Y면 true>, per_convention: {C7: true, C9: true}, notes: "...", confirmed_at: "<ISO>" }`. Claude가 여기에 `confirm_html` 경로 + (없으면) `confirmed_at` 보강해 milestones.json에 atomic write.
- `confirmed=false`(어떤 항목 N/skip)이면: 어느 convention이 화면에서 안 맞는지 명시 — fidelity 미스 → module-build 재빌드 or genre-decide 재검토 신호 (gmk-confirm은 판정만, 수정 안 함).

### Step 5 — Write back + resume (atomic, P8)
- milestones.json `confirm` 필드를 gmk-confirm 판정으로 갱신 (atomic). `confirm.status = "done"`.
- resume 갱신. Next: *"컨펌 done. confirmed=true면 /gmk-port (또는 fidelity INCONCLUSIVE면 이게 단독 gate). false면 어느 convention이 안 맞는지 보고 /gmk-module-build 재빌드."*

### What gmk-confirm does NOT do
- 빌드 안 함 (module-build). 검증(bot) 안 함 (validate). 수정 안 함 (판정만).
- "재미" 판정 안 함 — convention-anchored 관측만 (P2, concept §1).
- 외부 공유/배포 안 함 (컨펌 페이지는 로컬).
- 코드 리뷰 도구 아님 — 사용자가 코드 보겠다 하면 그게 S4 quit signal (STOP).
