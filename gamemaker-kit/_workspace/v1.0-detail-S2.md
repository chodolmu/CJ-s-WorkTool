### Step 1 — Pre-registration: 사용자가 아는 것 먼저 적기 (PASS baseline)

### Step 4 — Verdict: PASS/FAIL 판정 (self-report 비교)

이것이 S2의 *핵심* — concept §5 quit signal을 artifact-level로 집행.

1. `s2-test/known-conventions.md` (Step 1 pre-registration)와 `s2-test/research-notes.md` §Synthesis + `genre-decisions.json` conventions를 **나란히 비교**.
2. 각 research-surfaced convention에 대해 분류:
   - **KNOWN** — `known-conventions.md`의 K-항목과 의미적으로 매치 (사용자가 이미 알던 것).
   - **SURFACED-UNKNOWN** — K-항목에 *없던* convention (research가 새로 가져온 것).
3. **각 SURFACED-UNKNOWN에 mandatory 여부 판정 — artifact-level proxy (P2, M2)**: 이 convention이 mandatory인 *기계 검사 가능* 기준 = **genre-decisions.json에서 `acceptance != null` (숫자형 게이트 보유) OR `anti_tropes[]` 항목의 대척점**. 이 두 proxy 중 하나라도 해당하면 mandatory=true. *이것이 게이트* — feeling 아님.
4. **사용자 확인은 corroborating evidence (게이트 아님, M2)**: 사용자에게 *짧게* 물음: *"research가 가져온 이 항목들, 사전 목록엔 없었는데 — 이 중 '아 이건 진짜 중요한데 몰랐네' 싶은 게 있나요?"* 답변을 verdict에 *기록*하되, 사용자가 시큰둥해도 **artifact proxy가 mandatory면 PASS를 veto하지 못함**. (사용자 "eh maybe"가 객관적으로 surface된 mandatory convention을 feeling-FAIL시키는 것 방지 — P2.)
5. **PASS 판정 (D2 — artifact gate)**: SURFACED-UNKNOWN 중 **artifact-mandatory(`acceptance != null` OR anti-trope 대척점)가 ≥1개** → **PASS**. (Layer 1이 사용자 지식을 능가함을 artifact로 실증.) 사용자 인정은 evidence 필드로 동반 기록.
6. **FAIL 판정**: 모든 surfaced convention이 KNOWN이거나, SURFACED-UNKNOWN이 전부 artifact-non-mandatory(`acceptance == null` AND anti-trope 무관) → **FAIL** (Layer 1 research가 사용자 머릿속을 못 넘음 = concept §5 STOP 신호).
7. `s2-test/dogfood-verdict.md` atomic write:
   - PASS/FAIL
   - 표: research-surfaced conventions × {KNOWN / SURFACED-UNKNOWN} × {artifact-mandatory? (proxy 어느 것)} × {사용자 인정? (evidence)}
   - surfaced-unknown artifact-mandatory 목록 (PASS의 증거)
   - 학습 (§아래 학습 섹션 형식)
8. resume.md 갱신: `status: dogfood_pass | dogfood_fail`, "Step 4 verdict = {PASS/FAIL}, 다음 = S3 (PASS면) 또는 §7 분기 (FAIL면)".

**Artifact quit signal (Step 4 = S2 전체)**:
> `dogfood-verdict.md` 존재 + PASS/FAIL 명시 + (PASS면) surfaced-unknown **artifact-mandatory ≥1** (`acceptance != null` 또는 anti-trope 대척점 — 기계 검사). 사용자 인정은 evidence로 동반 기록되나 게이트 아님.

### Step 5 — Finalize (P8 — detail의 마지막 step)

1. resume.md 최종 atomic 갱신 (status, head_commit은 commit 후).
2. HANDOFF.md 갱신 — S2 결과 + 다음 액션(S3 또는 S1 RE-OPEN).
3. commit + push. commit 메시지: `feat(gamemaker-kit): S2 실행 — deck-builder dogfood {PASS/FAIL}`.
4. **stale 파일 commit 금지** (`.bkit/*`, `prepare-vendor.sh`, 부모 폴더 — git add 명시 경로만, S1 학습 함정).

## 7. FAIL 시 무엇을 학습으로 기록 (backlog dogfood 체크리스트)

S2 FAIL은 *나쁜 게 아님* — Layer 1 research 절차의 실측 한계를 드러냄. 기록 대상:

- **어느 단계가 thin했나** — eligibility / reference research / convention extraction / synthesis 중 어디?
- **사용자가 이미 알던 비율** — surfaced 중 KNOWN %가 높으면 Layer 1이 "검색해서 나오는 표면 정보"만 긁음 신호.
- **gmk-init 절차 개선 후보** — 구체적으로 어느 Step/Stage가 깊이 부족? (S1 RE-OPEN이 아니라 *별도 patch step* 후보로 — concept §P6 JIT).
- **장르별 dev-source 밀도 차이** — deck-builder가 merge3보다 dev-source 많/적었나? Layer 1 절차가 장르 의존적인가?

→ 학습은 `dogfood-verdict.md` §학습 + `v1.0-resume.md` §학습에 동시 기록. FAIL이어도 S2는 *완료*(verdict 산출이 완료 기준). 후속 patch는 별도 step.

## 8. 사용자 시간 cap (backlog dogfood 체크리스트 — concept §5 정신)

- S2 전체에서 **사용자 직접 입력은 3 지점만**: Step 1 pre-registration(~5분), Step 2 P9 pillar 비준 대화(~5-10분 — gmk-init Step 2.0 후보 제안 + Step 2/3 pillar refinement + anti-example까지라 conversational, ~3분은 낙관적), Step 4 mandatory 인정 확인(~2분). 총 ~12-17분.
- 그 외(research, 변환, verdict 작성)는 Claude 자율.
- **사용자 시간이 ~20분 초과하면 STOP + 보고** (concept §5 S5 quit signal 정신 차용 — dogfood가 사용자 시간 잡아먹으면 자율 모델 위반). 이 20분 backstop이 위 per-step 추정의 안전망.
