## 실패 시 Fallback

### Fallback 1 — Step 1 archive 브랜치 push 실패
- 원인 후보: remote permission / network / 브랜치 충돌
- 대응: 로컬 브랜치만 남기고 push는 나중에. v1.0 작업은 *로컬 archive 브랜치만 있어도* 진행 가능.

### Fallback 2 — Step 2 rm 후 다른 파일이 의존
- 원인 후보: 본 plan이 모른 v0.10 의존
- 대응: `git status` 확인 → 영향받은 파일 명시 → 사용자한테 보고 후 결정.

### Fallback 3 — Step 3 `ddbfb9b` push가 다른 변경과 충돌
- 원인 후보: 다른 세션이 main에 push함
- 대응: `git pull --rebase origin main` 후 재시도. 충돌 발생 시 사용자 컨펌.

### Fallback 4 — Stale 변경이 *우리 무관 아닌* 것으로 판명
- 예: `.bkit/state/memory.json`이 *실제로는* gmk-* SKILL이 쓴 것
- 대응: 의심되면 사용자한테 *그 파일이 무엇인지* 물어봄. 추측 commit 금지.
