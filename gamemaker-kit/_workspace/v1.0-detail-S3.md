## §3 충돌 해소 설계 (audit 액션 #7 — 핵심)

### 3.1 충돌의 정확한 위치 (파일 line 근거)

| SKILL | 충돌 지점 | 현재 (hypothesis-centric) | v1.0 요구 (fidelity) |
|-------|----------|--------------------------|---------------------|
| gmk-prototype | Step 3 (line 45-86) | pillar-bound Fun Hypothesis, `≥1 bot + ≥1 self-test` row 강제, 없으면 refuse | reference-clone module은 hypothesis 불필요 — convention acceptance가 gate |
| gmk-validate | Step 6 aggregate (line 248-251) | PASS = 모든 bot row CI 통과 AND guardrails | reference-clone module은 bot row 대신 convention acceptance 충족 여부 |
| gmk-port | precondition (line 24-27) | `validation.verdict==='PASS'` AND `self_test.latest_verdict==='PASS'` | fidelity-verdict PASS + 사용자 .html 컨펌으로도 port 가능 |

### 3.2 해소 메커니즘 — project mode 분기

**프로젝트는 두 모드 중 하나** (gmk-init이 결정, `pillars.json` 또는 `genre-decisions.json` 존재로 판별):
- **reference-clone mode**: `genre-decisions.json` 존재 (gmk-init → gmk-genre-decide 경로). gate = *fidelity*.
- **blank-page mode**: `genre-decisions.json` 없음, `pillars.json`만 (gmk-init blank-page pillar path, P9가 인정). gate = *hypothesis* (기존 v0.9 동작 그대로).

**판별 함수** (세 SKILL이 동일하게 사용, gmk-module-build §4 Step 1에 정의, 나머지는 cite):
```js
// project mode detection — single source, cited by prototype/validate/port
const hasContract = fs.existsSync('.gamemaker-kit/genre-decisions.json');
const mode = hasContract ? 'reference-clone' : 'blank-page';
```

**분기 규칙**:
- reference-clone mode → gmk-module-build가 primary 빌드 경로. gmk-prototype은 *blank-page용* (또는 reference-clone에서 사용자가 차별화 hypothesis를 opt-in으로 추가할 때).
- blank-page mode → 기존 gmk-prototype/validate/port 경로 *변경 없이* 작동 (회귀 0).

**핵심 불변식 (regression guard) — additive-only**: blank-page mode 동작은 변하지 않아야 함. 이를 *string presence*가 아니라 *control-flow preservation*으로 보장한다 (evaluator C1):

- **Additive 원칙**: reference-clone 분기는 기존 step/precondition을 *재작성하지 않는다*. 새 sub-step / sub-heading을 *기존 것 앞에 early-return guard로* 삽입한다. 형태: `if (mode === 'reference-clone') { <새 경로>; return/skip } else { <기존 블록 — 한 글자도 안 건드림> }`. blank-page는 guard를 통과해 *기존 블록에 도달*하며, 기존 블록 텍스트는 literal 불변.
- **금지**: 기존 unconditional 줄(예: gmk-port precondition "validation.verdict === PASS", gmk-validate "every bot row passes")을 `2'`/`6b` 식으로 *고쳐 쓰는 것*. 기존 줄은 그대로 두고, 그 *위에* reference-clone guard만 얹는다.
- **검증 (string-presence 아님)**: Step 7은 (a) 기존 블록 텍스트가 grep으로 *연속된 한 덩어리로* 여전히 존재하는지 (분산/재작성 아님) 확인 + (b) blank-page fixture(genre-decisions.json 없는 기존 milestone)에 대해 수정된 SKILL의 *서술 경로를 손으로 추적*해 기존과 동일 verdict 블록에 도달하는지 확인. SKILL은 산문이라 실행 diff 불가 → 추적 가능한 early-return 구조 + 기존 블록 literal 보존이 control-flow 보존의 검사 가능한 대리.

### 3.3 fidelity gate 정의 (P2 artifact-level)

reference-clone module의 PASS 조건 (전부 observable):
1. **Convention coverage**: module의 `covers_conventions[]` 중 `acceptance != null`인 convention 각각에 대해, bot trial이 측정한 metric이 `acceptance.{op, value}`를 만족. (`needs_metric: true` convention은 *coverage 대상에서 제외* — 기계가 gate 못 함, 사용자 .html 컨펌으로 넘김.)
2. **No-crash**: `crash_rate < 0.01` (기존 gmk-validate guardrail 재사용).
3. **사용자 .html 컨펌** (P5): module HTML을 사용자가 보고 **needs_metric convention 각각이 화면에서 관측되는지 Y/N** 확인 (§4 Step 5 per-convention 체크리스트). *feeling 판정 아님* — "convention C2가 화면에서 관측됨?" 같은 convention-anchored observable 확인이지 "재미있나/레퍼런스 같나" 같은 vibe 질문 아님.

FAIL = numeric convention 중 하나라도 acceptance 미달, OR crash_rate ≥ 0.01, OR 사용자가 fidelity 거부.
INCONCLUSIVE = module의 모든 convention이 `needs_metric: true` (기계 gate 불가) → 사용자 .html 컨펌 단독이 gate.

## §4 gmk-module-build SKILL 절차 (신규)

기존 gmk-* SKILL 형식 따름 (frontmatter + Why once + Precondition + Flow + What it does NOT do + Notes).

### Frontmatter
```yaml
name: gmk-module-build
description: Build one approved module from genre-decisions.json into a playable single-file HTML, gated by reference-fidelity (convention acceptance targets) instead of a fresh fun-hypothesis. Reuses gmk-prototype's HTML/bot-hook infrastructure and gmk-validate's 200-game trial, but the verdict is "does this match the researched conventions" not "is this a novel fun idea". Use when the user says "/gmk-module-build <Mn>", "build the module", "module 빌드", "M1 만들어", or after /gmk-genre-decide approved a module (the reference-clone-first path, Layer 2). Refuses without genre-decisions.json (that's blank-page mode → use /gmk-prototype).
model: sonnet
```
*(model=sonnet: 빌드는 실행 작업, opus 아님 — Tool CLAUDE.md 난이도 매핑 따름.)*

### Step 0 — Verify (disk + git, 첫 sub-step, P8)
1. `.gamemaker-kit/genre-decisions.json` 존재 + `JSON.parse` 성공 + `schema_version` 필드.
2. genre-decisions가 committed (git log) — 미커밋이면 STOP (S1.5 gmk-genre-decide의 Step 0 패턴 재사용).
3. 대상 module이 `modules[]`에 존재 + `status: "approved"`. draft면 STOP (*"M2는 draft. /gmk-genre-decide에서 approve 먼저, 또는 approved module 지정"*).
4. 실패 시 fallback: genre-decisions.json 없음 → *"이 프로젝트는 blank-page mode (genre-decisions.json 없음). /gmk-prototype을 쓰세요. reference-clone 하려면 /gmk-init → /gmk-genre-decide 먼저."* STOP.

### Step 1 — Read contract + detect mode
- §3.2 판별 함수로 mode 확인 (여기가 single source — 다른 SKILL이 cite).
- module entry 로드: `covers_pillars[]`, `covers_conventions[]`, `playable_html`.
- 각 covered convention의 `acceptance` + `needs_metric` 로드. numeric(acceptance≠null) vs qualitative(needs_metric) 분리.
- pillars[] 에서 covered pillar의 `kind` + `anti_example` 로드 (HTML 주석에 박을 trace용).

### Step 2 — Resolve module → build spec
- `playable_html`(genre-decide가 쓴 "무엇이 이 module을 playable로 증명하나") 를 빌드 스펙으로 해석.
- shape 결정: gmk-shape-advisor delegate (기존 재사용) — module의 mechanic에서 grid/continuous/dialogue/shader.
- 빌드 파일명: `prototypes/<Mn>-<slug>.html` (gmk-prototype과 같은 디렉토리/규약).

### Step 3 — Build HTML (gmk-prototype Step 5 인프라 재사용)
- **재사용**: single `<style>`, vanilla JS, `__gmk.makeHook(spec)`, line cap 300/600 (gmk-prototype-rules §2 cite), library Option A.
- **Canonical hook surface = gmk-prototype-rules §4 (M1, single source)**: author-facing spec은 `{reset(seed,rng), isOver(), legalActions(), apply(action), collectSummary()}` 5개 (prototype-rules §4 line 105-109). `__gmk.makeHook(spec)`이 이걸 wrap해 `window.__gmk_botHook__`의 `{startGame, act, summary, ...}` surface를 생산 — gmk-validate self-check(prototype-rules line 166)가 검사하는 게 *그 wrapped surface*다. 즉 `collectSummary` vs `summary`는 모순이 아니라 author-layer vs wrapped-layer. **이 detail은 author-facing 이름(`collectSummary` 등)만 쓴다.**
- **다름**: hypothesis header 대신 **fidelity header**:
  ```
  gamemaker-kit module: <Mn>
  Mode: reference-clone
  Covers conventions: C5, C12 (numeric), C2 (needs_metric)
  Covers pillars: <slug>
  Acceptance gates (machine):
    C5  energy_per_turn == 3
    C12 run_length_avg between [N, M]
  Confirm-only (needs_metric): C2 — <statement>
  Reference: <source_urls from convention>
  Created: <ISO-8601 +TZ>
  Shape: grid
  ```
- header는 gmk-validate가 *parse* (acceptance gate 추출). malformed = validate 시 refuse.

### Step 4 — Wire fidelity hook
- 각 numeric convention의 acceptance.metric을 hook의 **`collectSummary().custom.<metric>`** 에 넣도록 보장 (예: `collectSummary()` → `{ score, build_used:null, custom: { energy_per_turn: 3, run_length: 14 } }`). 라이브러리가 wrap → gmk-validate(§5.2 fidelity branch)는 wrapped **`summary().custom.<metric>`** 로 읽음 (M1 seam — prototype-rules §4 / line 167 "custom.*" deep-equal 보장 영역).
- acceptance.metric이 `collectSummary().custom`에 없으면 STOP (*"convention C5 acceptance metric `energy_per_turn`을 hook의 collectSummary().custom이 측정 안 함 — 추가하거나 convention을 needs_metric으로 강등"*).
- 이게 §3.3 fidelity gate의 기계 측정 가능성을 빌드 시점에 보장 (validate에서 metric 없어 silent INCONCLUSIVE 되는 것 방지 — M1 핵심).

### Step 5 — Confirm gate (P5 ★컨펌 게이트)
- module HTML을 브라우저에서 열고, **convention 단위 체크리스트**로 확인 (m1 — "처럼 보이나" 같은 vibe 질문 금지, observable convention만). needs_metric convention 각각을 한 줄씩:
  ```
  M1 빌드 완료. 브라우저에서 열고, 아래 각 항목을 화면에서 관측되는지 Y/N:
    C2 (needs_metric): <statement verbatim> — 화면에서 관측됨? [Y/N]
    C6 (needs_metric): <statement verbatim> — 화면에서 관측됨? [Y/N]
    ...
  (numeric convention C5/C12는 기계가 gmk-validate에서 잼 — 여기선 안 물음)
  ```
- 사용자 응답 기록 (구조화: `{confirmed: <모든 항목 Y면 true>, per_convention: {C2:true, C6:false,...}, notes: "..."}`) — feeling 판정 아니라 per-convention observable 확인.
- bot gate(numeric)는 gmk-validate가 별도로. 여기선 needs_metric convention의 사용자 .html 관측만.

### Step 6 — Register + resume (atomic, P8)
- milestones.json에 module entry append (gmk-prototype Step 6 schema 재사용 + `mode: "reference-clone"` + `covers_conventions[]` 필드).
- resume point 갱신 (atomic).
- Next 블록: *"빌드+사용자컨펌 완료. /gmk-validate <Mn> — convention acceptance를 bot으로 측정 (fidelity-verdict). 그 후 /gmk-port."*

### What gmk-module-build does NOT do
- 새 fun hypothesis 안 만듦 (그건 차별화 단계 = 사용자 opt-in gmk-prototype).
- "재미" 판정 안 함 (concept §1).
- blank-page mode에서 작동 안 함 (STOP → gmk-prototype).
- art-directed HTML 안 만듦 (wireframe-grade, gmk-prototype과 동일).

## §5 충돌 SKILL 수정 (최소 변경 — blank-page 회귀 0)

### 5.1 gmk-prototype — Step 0.5 추가 (additive, C1)
기존 Step 1~7은 *한 글자도 안 건드린다*. 기존 "## Preconditions" 뒤, Step 1 앞에 sub-step 1개 삽입 (§2 heading 표 — `.5` suffix로 번호 안 밀음):
```
### Step 0.5 — Detect project mode (early redirect guard)
genre-decisions.json 존재 시: "이 프로젝트는 reference-clone mode. approved module을 빌드하려면 /gmk-module-build <Mn>. 이 프로토타입은 *차별화 hypothesis*(레퍼런스에 없는 당신만의 아이디어)일 때만 — 맞나?" 사용자 yes면 *기존 Step 1로 그대로 낙하* (hypothesis 경로 불변), no면 gmk-module-build로 redirect (return).
genre-decisions.json 없을 시: blank-page mode — guard 통과, 기존 Step 1로 그대로 낙하.
```
Step 1~7 (Step 3 hypothesis 포함)은 *literal 불변* — blank-page와 reference-clone-차별화 둘 다 기존 경로에 도달. guard는 redirect만 할 뿐 기존 step 텍스트를 안 고침. ("falsifiable load-bearing" 한 덩어리 보존.)

### 5.2 gmk-validate — Step 6 분기 (additive, C1)
기존 "### Aggregate verdict" 블록(line 248-253)은 *한 글자도 안 건드린다*. 그 블록 *바로 앞에* early-return guard sub-heading 1개를 삽입:
```
### Aggregate verdict — fidelity branch (mode == reference-clone)  ← NEW, 기존 블록 앞에 삽입
milestone.mode === "reference-clone"이면 이 경로로 verdict를 산출하고 *기존 Aggregate verdict 블록을 건너뛴다*:
  - milestone의 covers_conventions[] 중 acceptance≠null 각각: bot이 측정한 metric (collectSummary().custom.<metric>, wrapped summary().custom로 읽음 — gmk-prototype-rules §4)을 acceptance.{op,value}와 비교.
  - PASS = 모든 numeric convention 충족 AND crash_rate < 0.01.
  - FAIL = numeric convention 하나라도 미달 OR crash_rate ≥ 0.01.
  - INCONCLUSIVE = 측정 가능한 numeric convention 0개 (전부 needs_metric) → 사용자 .html 컨펌이 단독 gate.
그 외(mode != reference-clone)면 아래 기존 블록으로 *낙하*.

### Aggregate verdict  ← 기존, line 248-253, 텍스트 literal 불변 ("every bot row passes" 한 덩어리 보존)
```
blank-page milestone은 `mode != reference-clone`이라 guard를 통과해 기존 "### Aggregate verdict" 블록에 *그대로 도달* — 텍스트도 도달 경로도 불변. verdict report (Step 7)는 어느 블록이 verdict를 냈는지에 따라 fidelity 또는 hypothesis 결과 출력.

### 5.3 gmk-port — precondition 분기 (additive C1 + observable self_test M2)
기존 precondition 2 / 3 (line 24-27, "validation.verdict === PASS" / "self_test.latest_verdict === PASS")은 *한 글자도 안 건드린다*. precondition 목록 *맨 앞에* reference-clone early-skip guard 1개를 삽입:
```
0'. (reference-clone only) milestone.mode === "reference-clone"이면 precondition 2·3 대신 아래를 검사하고 *기존 2·3을 건너뛴다*:
    - 2-rc: validation.verdict (fidelity) ∈ {PASS, INCONCLUSIVE} AND milestone.confirm.confirmed === true (gmk-module-build Step 5 사용자 컨펌, 구조화 필드).
    - 3-rc: self_test 검사는 *관측 가능한 필드값*으로 분기 (M2):
        · milestone.self_test === null  → SKIP (reference-clone module은 self-test 블록을 안 씀 — gmk-module-build Step 6이 self_test 필드를 쓰지 않으므로 null이 정상. "권장" 같은 영어 판단 아님, null 검사).
        · milestone.self_test != null AND latest_verdict === "PASS" → OK.
        · milestone.self_test != null AND latest_verdict ∈ {FAIL, INCONCLUSIVE} → STOP (사용자가 self-test 돌렸는데 실패 = 기존 hard-gate와 동일 취급).
    mode != reference-clone이면 이 guard를 통과해 기존 precondition 2·3에 *그대로 도달* (텍스트·경로 불변).
```
**M2 해소 근거**: reference-clone module이 port에 도달할 때 `self_test` 필드값이 *무엇인지* 명시 — gmk-module-build Step 6은 milestones.json entry에 self_test 블록을 *쓰지 않는다* (hypothesis 없는 module은 self-test row도 없음). 따라서 schema default `self_test: null`. precondition 3-rc는 그 *관측 가능한 null*에 분기하지, "권장/optional" 영어에 분기하지 않음. gmk-self-test SKILL은 *손 안 댐* (S4) — port는 self_test 필드를 *읽기만* 하고 그 값이 null/PASS/FAIL인지로만 판단하므로 S4 의존 없음.

Stage 1-6 본문은 변경 없음 (port의 *번역+재검증* 메커니즘은 mode 무관). **최소 삽입**: gmk-port는 이미 684줄(600 hard-cap 초과, split 후보) — guard 1개 sub-step만 추가, 본문 재작성 금지 (m2).

### 5.4 gmk-prototype-rules — 변경 없음
hook API / line cap / 결정적 seeding은 두 모드 공통 인프라. cite만, 수정 0. (audit이 지적한 "고아 SKILL" 중 gmk-prototype-rules는 v1.0에서 *공유 인프라 rulebook*으로 역할 유지 — 재배정 불필요.)
