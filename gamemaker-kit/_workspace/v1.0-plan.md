## 1. Premise + Scope

### Premise

사용자(시니어 게임 개발자, 회사에서 AX 분야, 1-2h/day)가 gamemaker-kit을 만든 진짜 동기:

> **"별다른 지시 없이도, 리서치를 통해, 게임다운 게임을, 스스로 계속, 입력 없이도 만들 수 있어야 한다."**

이는 γ 모델 — *seed 1회 + 가끔 점검*. α (완전 무인) 아님, β (sprint 자동만) 아님.

**Taste 문제 해법**: kit이 "재미"를 판정하는 게 아니라, **검증된 레퍼런스를 베끼는 것**으로 우회. 사용자가 *플레이하고 차별화 피드백*을 줄 때까지 kit은 clone 만듦.

### Scope (kit이 하는 것 / 안 하는 것)

| 하는 것 | 안 하는 것 |
|---------|-----------|
| Reference-clone-first 자율 게임 빌드 | 출시 도구 (별도 후속 작업) |
| 장르 컨벤션 자율 리서치 | IP boundary 관리 (사용자 책임) |
| Playable module 단위 milestone 진행 | "재미" judgment (사용자 피드백으로만) |
| Playable build마다 사용자 컨펌 | 차별화 디자인 결정 (사용자 피드백 기반) |
| 캐릭터 이름/스토리 *제외* 모든 베끼기 OK | 캐릭터 이름/스토리는 임의 채움 (사용자가 출시 전 교체) |

**핵심**: kit은 **clone-to-validate 단계의 도구**. 결과물을 직접 출시하지 않음. → IP 함정은 사용자 다운스트림 영역.

## 2. Architecture (Layer 1 / 1.5 / 2 / 3)

```
[사용자 인풋] seed (예: "merge3 / cozy / PC Steam / Royal Match 비슷한")
                        ↓
┌─────────────────────────────────────────────────────────────┐
│ Layer 1 — Autonomous Reference Research                     │
│   - 레퍼런스 게임 3-5개 분해 (WebSearch + WebFetch)              │
│   - 장르 mandatory conventions 추출                            │
│   - 플랫폼/모드 anti-tropes 추출                                │
│   - 출력: research-notes.md (kit 내부)                        │
└─────────────────────────────────────────────────────────────┘
                        ↓
┌─────────────────────────────────────────────────────────────┐
│ Layer 1.5 — Reference-to-Production Translation             │
│   - Research → Production spec 변환                          │
│   - 출력: genre-decisions.md (kit 내부 .md)                   │
│   - 출력: genre-confirm.html (사용자 컨펌용, 핵심 + 시각)        │
│   - ★ 사용자 컨펌 게이트                                        │
└─────────────────────────────────────────────────────────────┘
                        ↓
┌─────────────────────────────────────────────────────────────┐
│ Layer 2 — Module-Based Milestone Execution                  │
│   - milestone = 분리 가능한 playable module 1개                │
│   - 예 (Royal Match): M1=3매치 퍼즐 기본 / M2=아웃게임 /        │
│                       M3=인게임 스킬+BM / M4=에디터들            │
│   - 각 milestone 끝 = playable build 생성                     │
│   - ★ playable build마다 .html 컨펌 게이트                     │
└─────────────────────────────────────────────────────────────┘
                        ↓
┌─────────────────────────────────────────────────────────────┐
│ Layer 3 — (Deferred) Autonomous Loop Infrastructure         │
│   - Layer 1+1.5+2가 SKILL chaining으로 *manual*하게 ship       │
│   - dogfood에서 *구체적 반복 실패*가 surface되면 그때 신규 짓기      │
│   - v0.10 자산 (state_io / patch_guard / incident_classifier) │
│     은 *아이디어 참고*. 코드 그대로 재사용 아님                    │
└─────────────────────────────────────────────────────────────┘
```

**Layer 별 책임 분리** (중요 — Codex가 짚은 missing layer):
- Layer 1 = *연구* (정보 수집)
- Layer 1.5 = *번역* (연구 → 생산 가능한 spec). 이게 빠지면 Layer 1 결과가 prose로 끝나서 Layer 2가 못 씀.
- Layer 2 = *생산* (module 빌드)
- Layer 3 = *자동화* (보류, 필요 시)

## 3. Core Artifacts + Check-in Protocol

### Core Artifacts (3종)

#### `research-notes.md` (Layer 1 출력, kit 내부)
원시 리서치 결과. 레퍼런스 게임별 분해 노트. *runner가 직접 안 읽음*, Layer 1.5의 입력.

#### `genre-decisions.md` (Layer 1.5 출력, kit 내부 *primary reference*)
**v1.0의 root artifact**. runner/SKILL이 매 호출마다 fresh read.

```markdown
# Genre Decisions — {project-name}

## Seed
- 장르: {merge3 / 3-match / roguelite-deckbuilder / ...}
- 플랫폼: {PC Steam / mobile / ...}
- 톤: {cozy / cute / dark / ...}
- 사용자 원본 발화: "{verbatim quote}"

## References (3-5개)
- Royal Match: {핵심 모듈 / 차별점 한 줄}
- Gossip Harbor: {...}
- ...

## Mandatory Conventions (베낄 것)
- C1: {스와이프로 인접 2칸 교환}
- C2: {3개 이상 정렬 시 매치-깨짐}
- C3: {매치된 칸 위 블록 낙하}
- C4: {특수 매치(4개/5개/L자)로 아이템 생성}
- ...

## Anti-Tropes (제외할 것)
- A1: energy timer (PC Steam에 반함)
- A2: daily login reward
- A3: pay-to-skip
- ...

## Module Breakdown (= milestone list)
- M1: {모듈 이름} — playable scope: {scope}
  - Includes: C1, C2, C3
  - Excludes: A1, A2
- M2: ...
- M3: ...

## Differentiation Backlog (사용자 피드백으로 채워짐, 초기는 빈칸)
- (사용자가 M1 플레이 후 적는 자리)

## User Feedback Log
- (각 module 컨펌 후 사용자가 남긴 메모)
```

#### `module-N-confirm.html` (Layer 2의 각 module 끝, 사용자 컨펌용)
**시각 자료 + 핵심 위주**. 사용자가 1분 안에 컨펌/거부 가능해야 함.

```html
<!DOCTYPE html>
<html>
<head><title>{game-name} — M1 컨펌</title></head>
<body>
  <h1>M1: 3매치 퍼즐 기본 — 컨펌 요청</h1>

  <section>
    <h2>구현된 것</h2>
    <ul>
      <li>✅ 스와이프 (인접 2칸 교환)</li>
      <li>✅ 3개 정렬 매치-깨짐</li>
      <li>✅ 블록 낙하 + 빈칸 재충전</li>
      <li>✅ 4개 매치 시 가로/세로 클리어 아이템</li>
    </ul>
  </section>

  <section>
    <h2>스크린샷 / GIF</h2>
    <img src="screenshots/m1-match.gif">
    <img src="screenshots/m1-cascade.gif">
  </section>

  <section>
    <h2>플레이 방법</h2>
    <ol>
      <li>brower에서 `build/m1.html` 열기</li>
      <li>5-10분 플레이</li>
      <li>아래 피드백 박스에 메모</li>
    </ol>
  </section>

  <section>
    <h2>피드백 (genre-decisions.md에 박힘)</h2>
    <textarea>...</textarea>
  </section>
</body>
</html>
```

### Check-in Protocol

- **주기**: 모든 playable build 생성 시 (예: M1 끝, M2 끝, M3 끝...). 시간 기반 아님.
- **형식**: `.html` 시각 컨펌. core-only.
- **흐름**:
  ```
  Layer 2가 M_N 완료
    → playable build 생성 (HTML or 엔진 export)
    → module-N-confirm.html 자동 생성
    → 사용자한테 *"M_N 컨펌 요청"* 알림 (HANDOFF 또는 SKILL output)
    → 사용자가 컨펌/거부/피드백
    → 피드백 → genre-decisions.md의 [User Feedback Log] + [Differentiation Backlog]
    → 다음 module 자동 진입
  ```
- **사용자가 응답 안 하면**: kit은 다음 module 진입 보류, 무한 대기 (auto-progress 안 함). 사용자 우선순위가 *진척*보다 *컨펌*임.

## 4. Migration Rules

v0.9/v0.10 자산을 v1.0에서 어떻게 다룰지의 규칙. *세부 매트릭스는 부록 B*.

### Rule 1 — v0.9 SKILL 30+개 *전수 검토 대상*
v1.0은 *primary mode 자체*가 바뀌므로 모든 SKILL이 검토 대상. 기본 가정: *대부분 영향 받음*. (구체는 부록 B의 SKILL 매트릭스)

### Rule 2 — v0.10 auto-runner 코드 *재사용 아님*
`scripts/auto-runner.js`, `runner/*.js`는 *single-milestone bot-loop 형태*라 module-axis와 안 맞음. 코드는 **별도 브랜치 WIP commit으로 보존**, v1.0 본문에서 import 안 함. **아이디어**(atomic JSON write, heartbeat, classify table)는 v1.0 SKILL이 *처음부터 다시 짤 때* 참고.

### Rule 3 — bot infrastructure는 *secondary*로 강등
`_bot_hook_lib.js`, `gmk-validate`, `playtest-analyst` 등은 *regression/diagnostic* 도구로 유지. *primary 검증*은 reference fidelity (= module 사용자 컨펌).

### Rule 4 — `gmk-loop` SKILL 폐기 (primary loop로서)
*"One gate per call. The user is the recursion."* 철학이 γ 모델과 정면 충돌. v1.0의 primary loop는 *module 진행*. `gmk-loop`는 legacy interactive mode로 보존.

### Rule 5 — IP scope narrowing
캐릭터 이름/스토리 외 *모든 것 베끼기 허용*. kit이 IP boundary 검사 안 함. *모든 IP 결정은 사용자 출시-전 단계*.

## 5. v1.0-α Dogfood

### 대상 게임
- **장르**: merge3 (사용자 dogfood에서 이미 진행 중인 트랙 활용 가능성 검토)
- **레퍼런스**: Royal Match / Gossip Harbor / Triple Town (3-5개)
- **플랫폼**: PC Steam
- **톤**: cozy / casual

### Stop 지점
**M1 playable build까지만**. M1 = "3매치 퍼즐 기본" 모듈.
- 포함: 스와이프 + 매치-깨짐 + 낙하 + 4매치 아이템
- 제외: energy timer, daily login, 아웃게임, 메타 진행, 캐릭터, 스토리

### 검증 기준 (success criteria)
- [ ] Layer 1이 사용자 외부 리서치 *없이* research-notes.md 채워냄
- [ ] Layer 1.5가 genre-decisions.md 생성, *사용자가 그것을 보고* "맞아 이게 내 머릿속에 있던 거" 한 줄 가능
- [ ] Layer 2가 M1 playable HTML 빌드 생성, 사용자가 5-10분 *실제로 플레이* 가능
- [ ] module-1-confirm.html이 *1분 안에 컨펌 가능한 수준*으로 핵심 정리됨
- [ ] 사용자 피드백이 genre-decisions.md에 *실제로 박힘* (단순 textarea 저장 아니라 구조화)

### Stop 의도
M1까지로 멈추는 이유:
1. *전체 게임 빌드* 검증 아님. **워크플로** 검증.
2. M1만 잘 돌면 *M2, M3는 동일 패턴 반복*이라 자동 확장됨.
3. Layer 3 (자동화)는 *이 dogfood에서 어떤 반복 실패가 보이는지* 확인 후 결정.

## 6. Sequencing + Quit Gates

### 진행 순서

| Step | 산출물 | Quit Gate (멈춰야 하는 신호) |
|------|--------|----------------------------|
| **S0** | v0.10 freeze | Phase 0+1 코드 별도 브랜치 commit. main은 v1.0 작업으로. | (없음, 청소 작업) |
| **S1** | Layer 1 SKILL: `gmk-init` 재설계 | research-notes.md 생성하는 워크플로. WebSearch + WebFetch 활용. platform-aware. | *3회 시도해도 사용자 외부 리서치 떠먹여줘야 함* → Layer 1 자체가 LLM 한계 너머. v1.0 폐기 검토. |
| **S2** | Layer 1.5 SKILL: `gmk-genre-decide` (신규) | research-notes.md → genre-decisions.md 변환. Mandatory/Anti-trope/Module-breakdown 4분리. | *사용자가 genre-decisions.md를 보고 "이거 내가 직접 깎는 게 빠르겠다"* → Layer 1.5 design 잘못됨. 재설계. |
| **S3** | Layer 2 SKILL: `gmk-module-build` (신규) | module 단위 playable HTML 빌드 생성. genre-decisions.md의 [Module Breakdown]에서 다음 M_N 자동 선택. | *M1 빌드가 사용자 플레이로 "이건 내가 원한 게 아냐"* → module 정의 또는 reference 분해 잘못됨. S1-S2 재검토. |
| **S4** | Check-in SKILL: `gmk-confirm` (신규) | module-N-confirm.html 생성 + 사용자 피드백 → genre-decisions.md 반영. | *사용자가 confirm.html을 무시하고 직접 코드 들여다봐야 함* → 컨펌 형식 잘못됨. UI 재설계. |
| **S5** | dogfood M1 실행 | merge3 / Royal Match / cozy PC Steam seed → research → decisions → M1 빌드 → 컨펌. **Stop 지점**. | *M1 빌드까지 가는 데 사용자 시간이 1-2h 이상 들어감* → γ 모델 실패. 재설계 또는 v1.0 폐기. |
| **S6** | (Conditional) Layer 3 평가 | dogfood에서 *구체적 반복 실패*가 무엇이었나 분석. SKILL chaining으로 *못 푸는 것*만 자동화 후보. | *반복 실패 없음 또는 SKILL chaining으로 풀림* → **Layer 3 짓지 않음**. v1.0은 manual loop로 ship. |

### Quit Gate 원칙 (Codex 권고 반영)
- **"거의 됐어 한 phase 더만"** 함정 방어. 각 S에서 quit gate가 trigger되면 *진짜로 멈춤*.
- 사용자가 Claude 구독 해지 + Codex 이탈 고민 중. 정직성이 신뢰의 마지막 마일.
- v0.10에서 같은 함정에 들어갔다가 빠져나옴 (auto-mode Phase 2까지 가기 전에 root cause 재진단). v1.0은 *시작부터* quit gate 박음.

### 인라인 Risks (Codex Top 3, 각 Step 옆에 박힘)

- **S1 risk — Research theater**: 자료만 펼치고 결정으로 변환 안 됨. → S1→S2 사이에 *"research-notes.md가 비어있거나 prose만 있으면 S2 자동 reject"* 게이트.
- **S2 risk — Premature pillar**: Codex가 어제 짚은 함정. genre-decisions.md가 conventions/anti-tropes/module-breakdown까지 명시적 구조화 안 되면 다시 pillar 도출 함정. → S2의 출력 schema 강제.
- **S3 risk — Wrong-artifact automation**: module이 playable이 아닌데 자동 진행. → S3 끝마다 *"이거 사용자가 실제로 플레이 가능?"* check가 builtin.
