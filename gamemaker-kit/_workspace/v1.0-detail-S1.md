### Step 4 — Stage 3 (per-reference convention extraction, 3-cycle each)

**For each reference in Stage 2 shortlist**, run a 3-cycle loop:

**Cycle 1 — Baseline extraction**:
- 1 WebSearch: `"<reference title>" "<convention category>" design` for each convention category — **4 categories (Phase γ evaluator C1 — reduced from 6 to fit hard cap)**: `mechanics / progression / session-length / failure-mode`. Dropped: `monetization` (covered defensively by Stage 4 F2P filter) + `control-scheme` (low-actionability for S1 dogfood, can be inferred from mechanics).
- 1 WebFetch per top result (max 3 pages)
- Extract conventions into `conventions_draft.cycle1[]`
- Output captured in `research-notes.md` §Stage3 §<reference> §Cycle1

**Cycle 2 — Gap fill**:
- Read cycle1 draft → identify *missing* categories (any of the 4 above without ≥1 convention)
- 1 WebSearch per missing category with refined query
- 1 WebFetch per top result
- Append to `conventions_draft.cycle2[]`
- §Cycle2 in research-notes.md

**Cycle 3 — Cross-verification**:
- Read cycle1+2 conventions → for each convention claim, search for *one independent source*
- 1 WebSearch with query `"<convention claim verbatim phrase>" -<original source domain>`
- Mark each convention `verified: true` if independent source found, `verified: false` otherwise
- §Cycle3 in research-notes.md

**Per-reference quit signal**: `conventions_draft.cycle3` has ≥ 3 conventions across the 4 categories (mechanics / progression / session-length / failure-mode). If 3-cycle finishes with 0 conventions → STOP for this reference, log to research-notes.md `failures[]`, *continue sweep to next reference* (do not abort entire Step 4).

**Step 4 quit signal**: at least 1 reference has ≥3 conventions after cycle 3. If all references failed → STOP entire S1, ask user to revise seed.

### Step 5 — Stage 4 (F2P contamination filter — strict + exception)

For each convention from Step 4:

```
filter_decision(convention):
  if source_domain matches LISTICLE_PATTERN:    # "top-10-*", "best-*-of-202*", aggregator domains
    passed_filter = false
    filter_reason = "listicle/seo domain"
  elif source_type in {"marketing", "store-listing"}:
    passed_filter = false
    filter_reason = "marketing or storefront"
  elif source_type in {"dev-blog", "postmortem", "academic", "gdc", "interview"}:
    passed_filter = true
    filter_reason = "developer-grade source"
  else:
    passed_filter = false
    filter_reason = "unclassified — defaults to reject under strict mode"
```

**Exception slot** (locked decision #2 — 엄격 base + 예외 등록):
- If `passed_filter == false` but model can *justify* as developer-grade with a stated reason (e.g., a tweet by the original developer, an indie-dev youtube breakdown), record `exception_reason: "<reason>"` and treat as PASS for downstream synthesis.
- All exceptions logged in `research-notes.md` §Stage4 §Exceptions for user audit.
- Hard rule: exception cannot be "this looked useful" — must name a specific developer-grade indicator (named author who shipped the genre / first-party dev material / peer-reviewed reference).

**Quit signal**: every convention has `passed_filter` + `filter_reason` written. No convention left unfiltered.

**Across-genre quit**: `count(passed OR excepted) >= 5`. If <5 surviving → STOP, ask user "filter too strict OR seed mismatched genre — pick".
