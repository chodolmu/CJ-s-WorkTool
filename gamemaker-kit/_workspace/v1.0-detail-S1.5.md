## 0. 무엇을 / 왜

**무엇**: Layer 1 research의 *prose* 산출(research-notes.md §Synthesis)을 **기계가 파싱하는 production contract**(`genre-decisions.json`)로 변환하는 SKILL(`gmk-genre-decide`)을 신설하고, 그 schema를 정의한다.

**왜 (concept §3)**: Layer 1.5가 없으면 Layer 1 결과가 prose로 끝나 Layer 2(gmk-module-build)가 못 읽음. genre-decisions.json은 **Layer 2/3의 모든 호출이 fresh read하는 단일 진실원**.

**S1.5가 *아닌* 것**: module을 *빌드*하지 않음(S3). 새 게임을 research하지 않음(S1). 오직 *변환 + schema 정의 + SKILL 신설*.

## 4. genre-decisions.json schema (FINAL — Q1=c, Q2=a, Q3=a 반영)

```json
{
  "schema_version": "1.0",
  "kit_version": "1.0.0",
  "project_name": "<from seed>",
  "source_reference": {
    "seed": "<seed.json 요약>",
    "research_notes": ".gamemaker-kit/research-notes.md",
    "synthesized_at": "<ISO8601>"
  },
  "conventions": [
    {
      "id": "C1",
      "category": "failure | progression | mechanics | session",
      "statement": "<한 줄 convention>",
      "source_urls": ["..."],
      "cross_ref_strength": "genre-wide | family | single",
      "verified": true,
      "acceptance": { "metric": "<name>", "op": ">=|<=|==|range", "value": "<n 또는 [lo,hi]>" },
      "needs_metric": false
    }
  ],
  "_note_acceptance": "Q1=c: 숫자형 convention만 acceptance 객체. 정성형은 acceptance:null + needs_metric:true.",
  "anti_tropes": [
    { "id": "A1", "statement": "<피해야 할 것>", "flagged_by_refs": 2, "source_urls": ["..."] }
  ],
  "pillars": [
    {
      "id": "honest-tension",
      "ratification_label": "PC1",
      "name": "<ratified pillar name>",
      "kind": "sensory | behavioral | decision-shape | emotional",
      "from_conventions": ["C1", "C2"],
      "anti_example": "<violated when ...>",
      "acceptance": { "metric": "<name>", "op": "...", "value": "..." }
    }
  ],
  "_note_pillar_id": "id = pillars.json slug 공유 (name lowercased+hyphen, gmk-init Rule 17). ratification_label = research-notes의 PC{n} 원본 라벨 (추적용). 이 slug로 pillars.json과 동일성 매핑.",
  "modules": [
    {
      "id": "M1",
      "name": "<playable module 후보>",
      "covers_pillars": ["honest-tension", "instant-tactile-polish"],
      "covers_conventions": ["C1", "C7"],
      "playable_html": "<acceptance — what proves it works in HTML prototype>  (Q2=a: HTML 기준만)",
      "status": "draft | approved"
    }
  ]
}
```

**필드 type/required** (backlog 체크리스트):
- 모든 `id`: string, required, regex per D2.
- `conventions[].category`: enum, required.
- `conventions[].acceptance`: Q1 결정에 따라 required(b) / nullable(c) / pillar-only(a).
- `pillars[].kind`: enum (기존 gmk-init Rule 17 enum과 동일 — 호환).
- `pillars[].from_conventions`: array<C-id>, required ≥1 (P9 추적성 — 빈 배열 = reject).
- `modules[].status`: enum `draft|approved`. (Q3=a 확정 → modules[] 항상 생성.)

**Layer 2 파싱 (D1)**: `JSON.parse(read('.gamemaker-kit/genre-decisions.json'))`. schema_version 체크 → 필드 존재 assert → 끝. 정규식/AST 불요.

**schema 위반 reject 규칙**:
- `JSON.parse` 실패 → STOP.
- conventions/anti_tropes/modules id regex 불일치(`C\d+`/`A\d+`/`M\d+`) → STOP.
- `pillars[].id`가 slug 형식 아님(소문자+하이픈, gmk-init `id` 규칙) → STOP.
- `pillars[].from_conventions` 빈 배열 → STOP (P9 위반 — pillar가 research에 추적 안 됨).
- `pillars[].ratification_label`이 research-notes ratification 표의 PC{n} 중 *adopted*가 아님 → STOP. (id가 아니라 ratification_label로 대조 — id는 slug이므로.)
- `anti_tropes[].flagged_by_refs < 2` → STOP (research-notes AT 게이트와 일관, m4).

## 5. gmk-genre-decide SKILL — Step procedure (기존 gmk-* 형식)

> 실행 SKILL은 `skills/gmk-genre-decide/SKILL.md` (신규, atomic write). 아래는 그 내용 설계.

- **Step 0 — Resume/precondition verify**: (a) `.gamemaker-kit/research-notes.md` 존재 + §Synthesis 파싱 + ratification 표 존재, (b) **git에 S1 done 커밋 존재 확인** (`git log --oneline | grep` S1 / research-notes committed 상태 — concept P8 "git ref 존재" 요구, evaluator M3), (c) 내용 sanity(conventions count > 0). 하나라도 실패 → STOP("run /gmk-init first" 또는 "S1 uncommitted"). (disk+git 실검 — resume-first 룰)
- **Step 1 — Read synthesis**: §Synthesis confirmed conventions + anti-tropes + ratified pillars 로드.
- **Step 2 — Map conventions → JSON**: 각 confirmed convention을 `conventions[]` 엔트리로. source_urls/cross_ref_strength/verified 보존. acceptance는 Q1 정책 + 아래 *예상 분류표* (evaluator M1 — drift 방지):

  **예상 numeric/qualitative 분류 (실행 시 이 표와 대조; 벗어나면 STOP+이유 기록)**:

  | acceptance 객체 (numeric, ~7) | acceptance:null + needs_metric:true (qualitative, ~4) |
  |---|---|
  | C1 (~80% vanilla win-rate), C2 (average-moves near-miss), C5 (5 lives/30min), C6 (~every 10 levels), C8 (≤5min), C9 (moves 14-33→12-18), C10 (tier 3×/5×) | C3 (meta-narrative retention), C4 (star=single bridge), C7 (readable power-ups), C11 (single-currency) |

  **Hybrid 규칙 (C1·C9 — 과정+수치 혼합)**: 수치 target이 있으면 **numeric으로 분류**하고 acceptance에 그 수치를 박되, `statement`에 과정 서술을 보존. (C1 = acceptance{win_rate, ==, 80} + statement "data-driven tuning"; C9 = acceptance{late_move_count, range, [12,18]} + statement "move-compression".)

  **Acceptance count quit signal** (§6에 추가): `count(acceptance != null) == 7 ± 1`. 7에서 ±1 넘게 벗어나면 변환자가 정성형을 임의 숫자화했거나 숫자형을 떨군 것 → STOP.
- **Step 3 — Map pillars → JSON**: ratified pillars를 `pillars[]`로. `from_conventions` = synthesis의 C-id 추적(P9). kind 분류.
- **Step 4 — (Q3=a면) Derive module 후보**: pillars+conventions 커버하는 module 후보 도출 → 사용자 비준.
- **Step 5 — 사용자 컨펌 게이트** (concept ★게이트1): 변환된 genre-decisions를 사용자에게 요약 제시 → 승인/수정. kit이 임의 확정 금지.
- **Step 6 — Atomic write** `.gamemaker-kit/genre-decisions.json` + **gmk-init "Next:" 블록 조건분기 수정** (line 337-339: reference seed 있으면 `/gmk-genre-decide`를 최상단에, 없으면 기존 유지 — M2) + resume/HANDOFF. gmk-init 수정도 atomic.

**Frontmatter** (backlog SKILL 체크리스트): description(genre-decisions.json 생성, trigger: "/gmk-genre-decide", "genre decide", "contract 변환", "research를 spec으로"), model: opus(변환 판단 필요).
