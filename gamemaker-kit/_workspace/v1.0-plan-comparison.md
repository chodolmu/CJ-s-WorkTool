## 절충안 핵심 — 왜 이 3개가 *지금* 박혀야 하나

### Fix #1 — Machine-parseable schema (지금)
**왜 지금**: root artifact. Layer 2/3 *모든 호출*이 fresh read. prose면 *silent drift*.
**진행 중 처리 불가**: 이게 짜인 *후*에 Layer 2를 짜야 함. 순서 의존.

### Fix #2 — 모르는 장르 mini-dogfood (지금)
**왜 지금**: dogfood *자체의 validity*. 사용자가 merge3 너무 잘 알아서 Layer 1이 나빠도 본인 머릿속으로 채움 → *작동하는 것처럼 보이는 실패*.
**진행 중 처리 불가**: 진행 후 발견하면 dogfood 다 다시 돌려야 함.

### Fix #3 — Artifact-level quit gate (지금)
**왜 지금**: D8 failure mode 방어 = *"v1.0이 mid-quality로 작동하는데 gate가 안 발동"*. feeling-based면 motivated reasoning으로 회피.
**진행 중 처리 불가**: 진행 중에는 *이미 motivated reasoning 작동*. 시작 전에 박혀있어야 함.

### 나머지 6개는 *왜 진행 중*인가
- **#4 latency**: 첫 module 컨펌 wait 발생할 때 디자인. 그 전에는 *어떤 형태가 맞는지* 모름
- **#5 module decomp**: schema (#1) 짤 때 *자동 결정*. 지금 따로 결정 안 함
- **#6 playable 정의**: #1에 흡수. 별도 fix 아님 (Codex Q2)
- **#7 prototype-rules**: 매 SKILL touch마다 매트릭스 갱신. *지금 다 분류*는 그냥 prose 작업
- **#8 ddbfb9b**: ship-blocker 아님 (Codex). S0에서 처리
- **#9 Layer 1 비용 cap**: 실제 WebSearch 호출 패턴 본 후 결정. 추정으로 박으면 부정확
