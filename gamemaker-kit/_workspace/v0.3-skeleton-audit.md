## Audit 3 — agent 호출 경로 검증 ★★★ 가장 큰 발견

### 사실

- 4 agents 모두 자기 SKILL.md "When you are invoked" 섹션에 entry point 명시:
  - `systems-designer`: `/gmk-design-system`, `/gmk-port` Stage 1
  - `feel-engineer`: `/gmk-prototype` (continuous/shader), `/gmk-self-test` FAIL follow-up
  - `economy-balancer`: `/gmk-content-plan` follow-up, `/gmk-validate` dominant-strategy fail
  - `playtest-analyst`: `/gmk-validate` FAIL, `/gmk-self-test` FAIL, `/gmk-regression` drift, `/gmk-port` Stage 4 diff
- agent 산출물 디렉토리 (`system-spec.md`, `feel-numbers.md`, `feel-edits.md`, `economy-numbers.md`, `balance-rationale.md`, `playtest-diagnosis-*.md`) — CONCEPT.md에 정의됨.

### 그러나

| 사실 | 발견 |
|---|---|
| 4 agents가 자기 entry point로 명시한 SKILL들 | **K. 일방통행** SKILL.md 본문 중 어느 것도 agent를 *호출*하지 않음. `gmk-design-system`은 systems-designer를 reference 안 함. `gmk-prototype` shape 분기는 feel-engineer를 reference 안 함. `gmk-validate` FAIL 흐름은 playtest-analyst를 reference 안 함. |
| agent 산출물 (`system-spec.md` 등) | **L. structure.md drift** structure.md에는 이 파일들이 *정의 안 됨*. CONCEPT.md만 알고 있음. 즉 user가 structure.md만 보고 ".gamemaker-kit/`와 `_workspace/`에 뭐가 사는지" 알면 agent 산출물은 *유령 파일*. |
| `gmk-port` Stage 1의 systems-designer reference | "this skill, plus optional systems-designer agent in **Wave D**" — Wave D는 이미 끝났는데 *optional*로 영구 표기. **실질적으로 agent는 unwired**. |
| `gmk-loop` orchestration | 4 gate 모두 SKILL만 dispatch. agent로 라우팅하는 분기 0개. |

**해석**: **agent 4종은 형태만 존재 (skeleton-incomplete)**. 사용자가 `@systems-designer` 호출 시 작동은 함 (preconditions만 만족하면). 그러나 *gmk의 자동 워크플로 일부가 아님*. 사용자가 *수동으로* agent를 부를 줄 알아야 함 — 즉 4축 약속 중 "직군 축은 4 specialists가 강화"라는 약속이 *형태만* 지켜진 상태.

이게 v0.3의 **가장 큰 항목**.

## Audit 6 — 개발 완료 끝점 검증

**약속**: *"플러그인 안에서 게임 *개발*을 끝낸다. 사용자가 '이제 출시 준비만 하면 된다' 선언 시점이 gmk 끝점."*

### 끝점에 도달하는 경로

`gmk-loop`의 "shipped" 상태:
```
all of (validation PASS, self-test PASS, merge-gate PASS, port RE_PASS) 
  → "m2-dragon-evo is dev-complete. Next: pick another milestone (/gmk-status)."
```

즉 **마일스톤 단위의 dev-complete는 정의됨**. 그러나 **프로젝트 단위의 "개발 완료"는 정의 안 됨**. 

| 질문 | 답 |
|---|---|
| 모든 milestone이 shipped면 자동으로 "프로젝트 dev-complete" 선언? | 명시 없음 |
| 어디서 "이제 출시 준비만 하면 된다" 산출물이 생성? | 어디서도 생성 안 함 |
| release-readiness report (어떤 milestone이 shipped, 어떤 Pillar가 모두 검증됐는지 종합) | 없음 |
| gmk-status가 끝점에 도달했을 때 별도 메시지? | 없음 — 다음 milestone 권유 |

**S. 끝점 부재**: 프로젝트 레벨에서 "여기가 gmk 약속의 끝"이라고 알려주는 SKILL/산출물이 없음. v0.2 약속의 핵심 — "끝낸다" — 가 *형태로는* 약속됐는데 *작동으로는* 못 받음.
