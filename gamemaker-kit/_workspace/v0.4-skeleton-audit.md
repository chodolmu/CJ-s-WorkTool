# gamemaker-kit v0.4 Skeleton Audit

**Date**: 2026-05-15
**Goal**: v0.3 wiring 완료 위에서, dogfood 없이 잡힐 수 있는 *남은 뼈대 결함*을 모두 도출.
**Method**: 3-view audit (cold-read / adversarial / schema-first).
**Non-goal**: dogfood-driven findings. v0.4-backlog는 *이 audit 결과*에서만 도출.

3개 sub-audit:
- `v0.4-audit-coldread.md` — fresh eye로 SKILL/agent/templates 본문 점검
- `v0.4-audit-adversarial.md` — 사용자가 비정상 호출 시 어디서 깨지는지
- `v0.4-audit-schema.md` — milestones.json/pillars.json 데이터 모델 역추적

## 4. v0.4 backlog 제안 (Wave 분해)

### Wave α — Orphan flag 정리 (G1, G2)
1 SKILL = 1 *flag-spec* section 추가. `gmk-validate`, `gmk-port` 각각 정식 sub-flag 섹션. 모든 referenced flag가 정의됨을 grep으로 검증.

### Wave β — Precondition / state 일관성 (G3, AD-5, AD-9)
`gmk-prototype-rules`에 공통 precondition 섹션 추가 (또는 별도 SKILL `gmk-precond-resolve` 신규). 27 SKILL에 1-line citation. milestone-id resolution + empty state + refuse cycle 가드 일괄.

### Wave γ — Schema 통합 (G5, SC-1, SC-9)
1. `_workspace/examples/pillars-example.json` 추가
2. `_kill_reason` → `kill_reason` 정정
3. structure.md에 path convention / policy enum / touched_files 형식 명시
4. milestones.json 루트에 `kit_version` 필드 추가 + 마이그레이션 정책
5. write-only 9 필드 결정 — (a) mining SKILL 추가 또는 (b) deprecate

### Wave δ — Agent routing 표준화 (G6, CR-7, AD-10)
공통 agent-routing template block 정의 → 4 agents reference하는 모든 SKILL이 같은 형식 출력. agent precondition을 SKILL 본문에 인용.

### Wave ε — 운영 / 마이너 (G7, G8, CR-3, CR-5, CR-6, AD-4, AD-7, AD-8, SC-5, SC-10)
잔여 ★ 항목 정리. lock 만료 정책, plugin meta 자동 sync script, shader stale 카피 정정, `--bot-only`/`--force` semantics 명문화 등.

### Wave ζ — 릴리스 메타
CHANGELOG / plugin/marketplace v0.4.0 / HANDOFF.

| Wave | breaking? | 영향 |

## 8. 비교: v0.3 audit vs v0.4 audit

| 차원 | v0.3 audit | v0.4 audit |
|---|---|---|
| Method | 7-axis structural | 3-view (cold/adv/schema) |
| Defects 발견 | 18 (★★★ 2 + ★★ 5 + ★ 11) | 28 (★★★ 0 + ★★ 12 + ★ 16) |
| Backlog 규모 | 5 Wave (A-E) | 6 Wave (α-ζ) 제안 |
| Breaking 위험 | 없음 (스키마 변경 0) | Wave γ에서 부분 breaking |
| Dogfood 사용 | 미사용 (audit-only) | 미사용 (정책 확정) |

v0.3가 *큰* 결함 (★★★) 2개를 잡고 해소. v0.4는 *중간* 결함 (★★) 12개를 *묶음*으로 처리하는 형태. 따라서 v0.4는 *quality of life* 릴리스에 가깝다.
