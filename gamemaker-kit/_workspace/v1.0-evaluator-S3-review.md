§3.2 and §5 assert blank-page behavior stays "바이트 단위로 동일" and "기존 코드 한 줄도 안 지운다." But §5.3 (gmk-port) does NOT merely insert a branch — it *rewrites* existing precondition 2 into "2'." and precondition 3 into "3'." Turning them into mode-branched "2'/3'" is *editing the existing control-flow lines*, which contradicts the "한 줄도 안 지운다" invariant.

That string survives inside the new blank-page branch text, so the grep passes even though the blank-page reader now traverses a conditional it never had before. The guard verifies *string presence*, not *control-flow preservation* — exactly the back-door P8/Resume-Verification Rule warns about (concept line 139, "D8 drift back-door").

Wrapping them in `### 6b — Hypothesis-verdict (mode == blank-page OR ...)` means the blank-page path now executes a mode-gate before reaching the verdict it previously reached unconditionally.

**Fix**: Either (a) make the branch genuinely additive — a new precondition `2b`/sub-heading `6c` that *only fires when `mode === reference-clone`*, leaving the existing 2/3 and PASS/FAIL lines literally untouched and reached-by-default; OR (b) drop the "byte-identical / 한 줄도 안 지운다" wording and replace the §7 guard with a behavioral assertion ("blank-page mode, given no genre-decisions.json, reaches the same verdict block with the same inputs" — testable by running gmk-validate against an existing blank-page milestone fixture and diffing the verdict). ## Major

**M1 — Hook callback naming is ambiguous at the fidelity-gate core, and the two SKILLs the plan reuses already disagree.**
§4 Step 4 ("Wire fidelity hook") is the heart of S3 — it makes the fidelity gate machine-measurable by requiring `collectSummary()` to return each numeric convention's metric. But the two files the plan reuses use *different* callback names:
- `gmk-prototype/SKILL.md` line 139: required callbacks are `reset, isOver, legalActions, apply, collectSummary`.
- `gmk-validate/SKILL.md` line 38: smoke check requires `startGame, isOver, legalActions, act, summary`.

So `collectSummary` (prototype) vs `summary` (validate) — and `reset`/`apply` vs `startGame`/`act`. The plan inherits the prototype side without noticing gmk-validate (which actually *runs* the bot and computes the fidelity metrics in §5.2 6a) calls `summary()`. If Step 4's STOP condition asserts the metric is in `collectSummary` but gmk-validate reads `summary()`, the fidelity gate can silently measure nothing.

This is a *pre-existing* inconsistency in the two files (not introduced by S3), but S3 is the first skill whose gate *depends on the metric actually flowing from hook → validate*, so it surfaces here. **Fix**: §4 Step 4 must reference `gmk-prototype-rules` §4 as the single source of truth for the canonical hook surface and name the exact callback gmk-validate reads, OR add a one-line note that resolving the prototype-vs-validate name drift is a precondition.

**M2 — §6 self-test deferral has a hidden dependency in §5.3 port precondition 3'.**
The plan defers gmk-self-test reference-clone adaptation to S4 (§6, P6) and claims §5.3 only "mentions self-test as optional." But §5.3 precondition 3' actively *changes self-test semantics for reference-clone mode*. The real gmk-port (line 26-27) treats `self_test.latest_verdict === "PASS"` as a *hard* gate. Making self-test optional for reference-clone is a behavioral change to the port gate that depends on how gmk-self-test reports its verdict for a module that was never authored with a Fun Hypothesis.

Question the plan doesn't answer: when a reference-clone module (no hypothesis, no self-test rows) reaches gmk-port, what is `self_test.latest_verdict`? The port precondition 3' branch assumes a clean "optional" path, but the verdict field it reads is produced by a skill the plan explicitly does NOT touch. **Fix**: §6 must state what `self_test` field value a reference-clone module carries at port time (likely `null` if gmk-module-build §6 never writes a self_test block), and §5.3 3' must branch on *that observable value* (`self_test == null → skip`), not on a soft "권장/optional" English phrase (itself borderline-P2 vague).
